# 寻迹 · 用户测试脚本 v1

> 测试目标：验证 3 件事
> 1. 用户能不能自己走完"首页→选路线→看详情→想打卡"这条链路
> 2. 哪里卡住、哪里困惑、哪里不想点
> 3. 用户愿不愿意把这条路线推荐给朋友

## 测试对象
- 5-10 人
- 优先找：喜欢旅行 / 喜欢文学或文化 / 用过小红书找旅游攻略的人
- 不需要技术背景，反而越不懂技术越好
- 每人 20-30 分钟，当面或视频通话都行

## 测试前准备
| 物品 | 说明 |
|---|---|
| 测试设备 | 用户自己的手机（看真实体验），或一台测试手机 |
| 测试网址 | http://47.109.91.112:8080 |
| 录屏 | 征得同意后录屏（手机自带录屏或 Zoom 录屏） |
| 记录表 | 用后面的"测试记录表"打印或建一个在线表格 |

**注意**：不要解释产品怎么用，不要帮用户操作。

## 开场话术（照念即可）
"我在做一个叫「寻迹」的文化旅行产品，想请你帮我体验一下。你不需要懂技术，我主要是想看你用起来顺不顺手。过程中你想到什么就直接说，不用客气。我会在旁边观察和记录，有问题随时可以问我。"

## 测试流程（6 步，每步 2-5 分钟）

### 第 1 步：首页第一印象（2 分钟）
**指令：** "你打开这个网址，先看看首页，告诉我你看到了什么。"

**观察点：**
- 用户的视线先落在哪里
- 动效播放时用户有没有等待还是想跳过
- 用户���不能一眼看出这个产品是干什么的
- 用户有没有注意到"开始寻迹→"按钮

**追问（看完后）：**
- "你觉得这个产品是做什么的？"
- "如果你朋友发给你这个页面，你会点进去看吗？为什么？"
- "首页上有什么东西让你想多看一眼？有什么让你觉得多余？"

**记录：**
- ☐ 用户 10 秒内能说出产品用途
- ☐ 用户主动点了"开始寻迹→"
- ☐ 用户提到了动效（正面/负面/无感）
- 卡点记录：____________

### 第 2 步：选一条路线（3 分钟）
**指令：** "你想看看有哪些路线可以选，找一条你感兴趣的点进去。"

**观察点：**
- 用户能不能找到 /routes 路线列表页
- 用户选路线时看什么信息（城市？标题？封面图？点位数？）
- 用户有没有注意到游戏和音乐版块
- 有没有犹豫不决或迷路

**追问：**
- "你为什么选这条？"
- "其他路线你会想看吗？哪些不会？为什么？"
- "你觉得'人间滋味'是什么意思？'枫桥夜泊'呢？"

**记录：**
- ☐ 用户 1 分钟内进入了某条路线详情页
- ☐ 用户能区分书籍/游戏/音乐三个版块
- 用户选择的路线路径：首页→____ 或 /routes→____
- 卡点记录：____________

### 第 3 步：路线详情页体验（5 分钟）
**指令：** "你现在已经进入了一条路线，看看这个页面，告诉我你看到了什么。"

**观察点：**
- 用户有没有注意到地图
- 地图有没有正常加载（如果还是"加载中"就记录）
- 用户有没有看文学原文摘录
- 用户能不能理解每个点位是什么
- 用户的阅读顺序是什么（先看地图？先看文字？先看卡片？）
- 用户有没有滚动到底部
- 用户有没有注意到打卡按钮
- 用户有没有注意到评价区域

**追问：**
- "这个页面你第一眼看的是什么？"
- "你觉得到每个点位可以做什么？"
- "文学原文你看完了吗？觉得有意思吗？还是太多了？"
- "地图上那些点你看得懂吗？你知道怎么去吗？"
- "如果现在让你去扬州走这条路线，你觉得这个页面够你用吗？缺什么？"

**记录：**
- ☐ 地图正常加载并显示点位
- ☐ 用户阅读了至少 1 段文学原文
- ☐ 用户注意到打卡功能
- ☐ 用户注意到评价功能（如果有评价数据）
- 卡点记录：____________

### 第 4 步：打卡流程模拟（3 分钟）
**指令：** "假设你现在站在富春茶社门口，你想打卡，试试看怎么操作。"

**操作方式（二选一）：**
- 如果在场测试：让用户真的点打卡按钮看会发生什么
- 如果远程测试：告诉用户"假装你现在在富春茶社"，看用户怎么找打卡入口

**观察点：**
- 用户能不能找到打卡按钮
- 用户点之前有没有犹豫
- 打卡成功/失败后用户的反应
- 用户对"距离 XX 米"的提示理解不理解
- 打卡后用户有没有注意到卡片解锁

**追问：**
- "你觉得打卡这个功能是干嘛的？"
- "打卡完之后你期待发生什么？"
- "你会不会为了打卡专门跑到这个地点？"
- "如果打卡太难（距离太严），你会怎么办？"

**记录：**
- ☐ 用户成功完成 1 次打卡
- ☐ 用户理解打卡需要到现场
- ☐ 用户注意到卡片解锁变化
- 卡点记录：____________

### 第 5 步：评价与分享（3 分钟）
**指令：** "打卡完了，你能不能给这个点位评个分？或者写一句话？"

**观察点：**
- 评价面板是否弹出
- 用户评分时有没有犹豫
- 用户愿不愿意写文字
- 用户有没有注意到"生成分享图"功能
- 分享图生成后用户愿不愿意保存/分享

**追问：**
- "你会不会把这张分享图发朋友圈或小红书？为什么？"
- "你觉得分享图上少了什么？多了什么？"
- "如果朋友看到你发的这张图，ta 会不会问这是什么？"

**记录：**
- ☐ 用户完成 1 次评价提交
- ☐ 用户尝试生成了分享图
- ☐ 用户表示愿意/不愿意分享，原因：____________
- 卡点记录：____________

### 第 6 步：收尾访谈（3 分钟）
**指令：** "最后几个问题。"

**问题清单：**
1. "整体体验下来，你觉得这个产品最吸引你的地方是什么？"
2. "最让你困惑或不舒服的地方是什么？"
3. "如果你要去扬州旅行，你会用这个产品吗？为什么？"
4. "你觉得这个产品收多少钱你觉得合理？免费的你会用吗？"
5. "你觉得谁会喜欢这个产品？你身边有没有这样的人？"
6. "如果只能改一个地方，你希望改什么？"

**记录：**
- 用户最认可的功能：____________
- 用户最不满意的地方：____________
- 用户是否愿意使用（会/可能/不会），原因：____________
- 用户愿意付的价格区间：____________
- 用户推荐意愿（1-10 分）：____
- "只改一个地方"用户选的：____________

## 测完后做 3 件事
1. **统计卡点热力图** — 哪一步卡的人最多，那就是下一个要修的地方。
2. **收集"只改一个地方"的答案** — 出现 ≥2 次的相同答案，直接列为下一轮迭代优先级。
3. **写一份 ≤10 行的测试总结** — 格式：
   > 测了 X 人，Y 人走完了全流程。最卡的是第 N 步。N 人愿意推荐，平均分 X/10。最多人想改的地方是：xxx。下一步建议先修 xxx。

## 已知风险（测前心里有数，但不要替用户发现）
1. **HTTP 站点 GPS 被禁用** — 线上是 HTTP，移动端真实 GPS 被浏览器禁用。详情页有"体验模式"可模拟打卡，但入口是否明显待验证（重点观察项）。
2. **坐标是 GCJ-02 近似值**，未实地核准 — 用户若熟悉当地可能发现标记偏移。
3. **首页动效约 3.5 秒** — 性子急的用户可能直接滑动，需观察动效是否"打扰"。
4. **无用户登录** — 打卡/收藏记录只存本地 localStorage，换设备/清缓存会丢。

## 本轮重点观察（v1.1 追加 · 2026-07-29 晚）

> 上一轮测试暴露的三大卡点（体验模式发现 / 游戏板块理解 / 音乐板块理解）已做修复，本轮重点验证修复是否生效。原有 6 步流程不变，以下是每步里要重点盯的观测点。

### 观测点 1：体验模式（对应第 4 步·打卡）
- [ ] 用户**无需主持人提示**，自己看到/找到"体验模式"入口（目标：≥50%）
- [ ] 用户能说出体验模式是干什么的（"模拟打卡""不用真的到那也能打卡"）
- [ ] 开启体验模式后，用户**注意到页面状态变化**（顶部黄色状态条 / 按钮变"体验打卡"）
- [ ] **反向**：关闭体验模式且无法定位时，用户看到明确提示（不会"静默失败/以为坏了"）
- 判定标准：5 人里 ≥3 人自己找到 = 通过；0-2 人 = 入口仍不够明显，继续改。

### 观测点 2：游戏板块（对应第 2 步·选路线 + 首页点"游戏"Tab）
- [ ] 用户进入游戏板块后，**10 秒内能说出**"这是找游戏/影视场景对应的现实地方"
- [ ] 用户注意到板块首页的"一句解释"白话说明
- [ ] 用户点进张家界路线详情，看到"这是什么 · 跟着游戏与影视里的悬浮山…"并理解
- [ ] 用户不再说"看不懂 / 不知道怎么玩 / 关系不清楚"
- 判定标准：5 人里 ≥4 人 10 秒内说清 = 通过。

### 观测点 3：音乐板块（对应第 2 步 + 首页点"音乐"Tab）
- [ ] 用户进入音乐板块后，**10 秒内能说出**"这是跟着一首词/一首歌去走城市"
- [ ] 用户不再问"这个音乐路线到底是听什么"
- [ ] 用户点进扬州慢详情，看到"这不是听歌打卡，而是跟着词里的地名去走扬州"并理解
- 判定标准：5 人里 ≥4 人 10 秒内说清 = 通过。

### 观测点 4：三类板块首屏一致性（对应第 3 步·详情页）
- [ ] 随机打开 1 条书籍（扬州汪曾祺）、1 条游戏（张家界）、1 条音乐（扬州慢）路线
- [ ] 三者首屏都有："这是什么 · …" + "为什么值得去 · …" 两块说明
- [ ] 用户不会觉得三类是"不同产品"

### 本轮核心判定
- 如果**观测点 1/2/3 全通过** → 理解成本问题已解决，下一轮可转向内容扩充或商家演示。
- 如果**任一未通过** → 记录用户原话，把卡点写进下一轮 PROGRESS.md 优先级。
- 特别警惕：用户若仍说"以为功能坏了"，说明体验模式入口还需进一步前置（哪怕牺牲一点美观）。
