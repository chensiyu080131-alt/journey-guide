## 〇、写在前面：我们现在站在哪

黑客松 v0.2 已经把「常熟 Demo 静态站」跑成了**可服务端 AI 生成、可全国扩展**的文学旅行平台。刚完成的一次迭代合并又带来三个结构性变化，决定了下一阶段的起点：

1. **从「寻城」升级为「寻迹」** —— 品牌与叙事从「跟着书本去旅行」扩展到**书·影·游·音·动五类文化载体**（Slogan：有迹可循，寻迹而至）。产品定位从「文学旅行」升维到「**文化地理引擎 / 文化翻译器**」。
2. **「迹录员 JiluFloat」成为核心交互入口** —— 可拖拽的 AI 伙伴取代了原「跟书旅行浮窗」，具备对话、攻略生成、跳转带地图攻略页（`/guide/jilu`）的能力，是全站唯一的常驻 AI 触点。
3. **服务端 AI 架构收敛** —— 所有 AI 能力统一走 `/api/chat`、`/api/book-guide`、`/api/generate-guide`，密钥仅在服务端；地图运行期注入高德 Key 修复了线上不显示问题。技术底座比 v0.2 更稳。
4. **可打卡路线成为体验北极星（v0.4）** —— 王林落地的扬州汪曾祺早茶线证明：用户要的是「走到点上、核对原文、打卡解锁」，不是又一篇攻略 HTML。后续内容与功能以此为验收模板。

**一句话判断：** 骨架已成、Demo 能打，且已有一条**现场可验证**的标杆线；v0.4 的核心任务是**把标杆模型复制到更多书×城，并把可信度/打卡闭环做深**。

## 一、下一阶段战略主线（3 条）

> 功能会很多，但只围绕三条主线取舍。凡不服务这三条的需求一律降级。

### 主线 A：可信度是唯一的护城河
LLM 做旅游最大的风险是幻觉，而**县城 / 冷门书目的训练数据最稀薄，幻觉最严重**。谁能把「书里写的 = 脚下走的」做到可验证、可追溯、可纠错，谁就赢。这是寻迹区别于「通用 AI 旅游助手」的根本。

### 主线 B：迹录员是产品的「人格化入口」
用户不该面对一堆表单和 Tab，而该面对**一个懂书、懂城、懂你的旅伴**。迹录员要从「会聊天的浮窗」进化成**贯穿行前规划—行中陪伴—行后回顾的 Agent**。它是留存与差异化的核心。

### 主线 C：内容飞轮 + B 端造血
LLM 生成解决冷启动的「广度」，但**深度内容**要靠三方共建：AI 生成 → 用户/达人纠错共创 → 文旅局官方背书。B 端（文旅局工作台）既是收入来源，也是权威内容的注入口。两者互相喂养形成飞轮。

## 二、分阶段路线图

### 近期 · 1 个月内（打磨可信度 + 补齐已挖的坑）

| 优先级 | 事项 | 说明 / 验收 |
|---|---|---|
| **P0** | **引文可信度分级** | 每条书中引文标注来源：`用户摘录`／`已验证原著`／`AI 推断`（三级色标），前端明示。AI 推断内容加免责提示 |
| **P0** | **用户纠错反馈闭环** | 每个点位/引文旁「纠错」入口，收集「地点不对/引文有误/已关闭」→ 落库 → 人工或规则回灌，形成可信度迭代数据 |
| **P0** | **生成提速** | 跟书旅行两次 LLM + POI 串行约 1–2 分钟，太慢。做：地点提取与 POI 验证并行、热门「书×城」结果预生成缓存、流式先出摘要再补行程 |
| **P0** | **地图稳定性根治** | 蓝格问题（Key 白名单/容器尺寸/StrictMode 双初始化）彻底排查；`osm-map-fallback` 作为兜底自动切换 |
| **P1** | **迹录员生成结果可落地** | 迹录员对话生成的攻略 → 复用 `/api/book-guide` 的 POI 验证管线（而非纯文本），保证有真实坐标进 `/guide/jilu` 地图 |
| **P1** | **互动任务挂真数据** | 诗词诵读/知识问答/古籍寻宝/书法临摹的 Mock → 至少常熟 4 条线各挂 1 个真任务 |
| **P1** | **江苏 10 城书单补全** | 已有 hub 的城市补齐书单与至少 1 条可跑通攻略 |
| **P2** | **LLM 输出评测集** | 建 30–50 条「书→地点」黄金样例，每次改 Prompt 跑一遍，量化准确率，防止改坏 |

### 中期 · 1–3 个月（迹录员 Agent 化 + 多载体填充）

| 优先级 | 事项 | 说明 |
|---|---|---|
| **P0** | **迹录员：行中助手模式** | 基于时间/位置推「现在还能去哪」「下一站怎么走」；进入攻略页后可对当前路线增删改（「把 Day2 换成美食线」） |
| **P0** | **多文化载体真正落地** | 把影视/游戏/音乐/运动 Tab 从占位变内容：影视取景地（繁花·上海、长安三万里·西安）、游戏取景（原神·张家界、黑神话·山西古建）、音乐（地方戏曲/民谣→实地）、运动（Citywalk/骑行/徒步）。每类各上线 2–3 条标杆线 |
| **P1** | **迹录员记忆与画像** | 跨会话记住用户偏好（喜好载体/城市/预算），下次直接个性化推荐；`saveJiluGuide`/`loadJiluGuide` 扩展为用户级 |
| **P1** | **RAG + 文化地理知识库** | 把「书—人—地—非遗」结构化入库（先常熟+江苏），检索增强，降低幻觉、提升冷门书命中 |
| **P1** | **B 端工作台产品化** | 白皮书从 Mock → 真生成（走 POI 验证）；资产看板接真实数据（路线数/原文点位/城市覆盖）；官方路线「发布」能力（文旅局审核后对 C 端可见并打「官方」标） |
| **P2** | **相机识景（AR 雏形）** | 拍建筑/碑文 → 识别 → 弹书中段落+历史故事（先做识别+文案，AR 3D 后置） |

### 长期 · 3–12 个月（内容飞轮 + 规模化 + 商业闭环）

| 方向 | 说明 |
|---|---|
| **UGC「我的家乡」模式** | 本地人/达人贡献路线与纠错，审核后入库并署名，反哺平台，解决 LLM 覆盖不到的深度 |
| **内容飞轮成型** | AI 生成（广度）→ 用户纠错+达人共创（深度）→ 文旅局官方背书（权威）三层内容分级并互相喂养 |

| **B 端商业化** | 文旅局白皮书与官方路线定制（SaaS 订阅 + 定制费）；研学机构/图书馆/出版社联名；政策对接「十五五 县域旅游+智慧旅游」 |
| **生态合作** | 与出版社（书目授权+导流购书）、地方戏曲院团、游戏厂商（取景地联动）、高校研学做内容与渠道合作 |

## 三、关键指标（North Star & 分层）

- **北极星（v0.4）：** 每周「完成至少 1 次现场打卡（或等效模拟）并解锁结果物」的用户数
- **供给层：** 每周「生成并被完整查看」的可信攻略 / 可打卡路线数
- **可信度层：** 原文实据点位占比、主题引用占比、出处待考占比、用户纠错率（下降趋势）
- **参与层：** 路线页停留、打卡完成率、文学卡片解锁数、分享图导出数
- **增长层：** 新增可打卡路线数、分享转化、B 端洽谈→签约数
- **对标参考（产品开发书援引）：** 「AI 游利川」停留+30%、二次消费+45%、投诉-32% —— 作为体验指标标杆

## 四、技术演进重点

1. **抗幻觉三板斧升级为四板斧**：摘录优先 + POI 验证 + 地点表锁定 +（新）**RAG 知识库**。
2. **生成性能**：并行化管线、结果缓存/预生成、流式渐进渲染，把 1–2 分钟压到 30 秒内可见首屏。
3. **可观测与评测**：LLM 输出黄金评测集 + 线上纠错回流，形成质量闭环；成本监控（token/城市）。
4. **地图**：高德为主 + OSM 兜底自动切换；运行期 Key 注入已修复，需补容器尺寸/StrictMode 防抖。
5. **架构**：AI 全部服务端代理已收敛；后续把迹录员的攻略生成、AI 书灵、文学侦探统一到一套「带 POI 验证的生成服务」，避免多套 Prompt/Mock 分裂。

## 五、风险与应对

| 风险 | 应对 |
|---|---|
| **LLM 幻觉（县城尤重）** | RAG + POI 验证 + 引文分级 + 用户纠错；未验证内容明确标注，不隐藏 |
| **内容深度不足（LLM 只能给广度）** | UGC + 达人共创 + 文旅局官方内容三层飞轮 |
| **生成慢导致流失** | 缓存/预生成热门书城、并行化、流式先出摘要 |
| **B 端销售周期长** | 先做常熟标杆案例 + 可量化数据看板，用案例撬动同类县域 |
| **单人/AI 协作产能** | 聚焦三条主线，砍掉非核心；用评测集守住质量下限，敢于让 AI 批量产内容 |
| **多文化载体摊子铺太大** | 每类载体先做 2–3 条标杆线验证模型，再决定是否规模化，不平均用力 |
