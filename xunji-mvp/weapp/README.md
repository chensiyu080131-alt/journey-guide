# 寻迹 微信小程序（MVP · 最短路径）

> 验证「传统文学 + 现代文旅」商业闭环的最小可跑产品。当前版本跑通：**选诗 → 看路线 → 到景点打卡 → 解锁文学卡片**。
> 全程**零付费第三方服务**，默认本地模式游客即跑；填 AppID 可一键切云端。

## 运行方式
1. 安装「微信开发者工具」→「小程序」→「导入项目」，目录选本 `weapp/` 文件夹。
2. AppID 先用 `touristappid`（游客模式可立即预览）；正式联调替换为自己的小程序 AppID。
3. 编译即可在模拟器运行。地图、导航、搜索、GPS/演示打卡、卡片墙、数据面板、分享海报**全部本地驱动，无需后端**。

## 页面结构
| 页面 | 路径 | 功能 |
|------|------|------|
| 文学路线（首页/tab） | `pages/index` | 诗词路线卡片列表 + 关键词搜索（诗名 / 作者 / 城市） |
| 路线地图（详情） | `pages/route` | 地图标点 + 一键导航 + 每景点 AI 导览（原文/解读/背景/任务）+ GPS 打卡 + 演示打卡 |
| 我的卡片（tab） | `pages/cards` | 已解锁文学卡片墙 + 收集进度 + 生成分享海报（Canvas 2D） |
| 数据面板（tab） | `pages/dashboard` | B 端：参与人数 / 累计打卡 / 打卡热力 / 用户画像；云端模式为真实统计，本地模式为模拟聚合 |

## 数据层（本地模式 ↔ 云端模式 同源）
- 所有页面只通过 `utils/service.js` 取数 / 打卡，**不直接 require 数据层或 store**，切换模式无需改页面。
- **`USE_CLOUD=false`（默认）**：直读 `data/routes.js`（镜像 `../db/literary-routes.json`，10 诗 / 20 景点 / 10 路线）+ 打卡存本地 `Storage`。游客模式即跑。
- **`USE_CLOUD=true`**：走微信云开发，数据来自 `cloudfunctions/getRoutes`，打卡来自 `cloudfunctions/checkin`，B 端统计来自 `cloudfunctions/stats`。需自有 AppID + 已开通云环境（详见 `../BLOCKED.md`、`cloudfunctions/README.md`）。

## 打卡逻辑
- 真机：`wx.getLocation`（GCJ-02）与景点坐标算 Haversine 距离，**200 米内**自动解锁（需在 `app.json` 声明的定位权限）。
- 模拟器 / 无定位权限：点「演示打卡」直接解锁（保证可演示）。
- 本地模式解锁记录存 `Storage`；云端模式写入云数据库 `collections` 集合。

## 本地自测（无需微信开发者工具）
```
cd xunji-mvp
node selftest.js          # 本地模式：28 项断言全过
node selftest.js --cloud  # 模拟云端模式：34 项断言全过（验证切云端不崩，含 stats 真实统计）
```
`selftest.js` 用 mock 的 wx/Page/getApp 真实执行页面逻辑，是「免费试点演示」的最小化运行验证。

## 数据来源与边界
- 内容库单一数据源 `../db/literary-routes.json`；坐标 GCJ-02 取自公开地图，仅供演示；AI 解读为模板示例，**上线前需人工审核**。
- 本小程序未新增任何付费第三方服务、未搭独立后端服务器；仅新建小程序目录，符合任务书「界限」。
